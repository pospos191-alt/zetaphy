# แอร์ดรอป ZTPHY รอบที่ 1: สำหรับผู้ถือ SWD

[English](AIRDROP-ROUND1.md) · ภาพรวมการทำงานของแอร์ดรอป: [AIRDROP.th.md](AIRDROP.th.md)

แอร์ดรอป ZTPHY รอบแรกนี้สำหรับคนที่ถือ **SWD บน Solana** ZTPHY คือเหรียญหลักของเมนเน็ต ZETAPHY
(`zetaphy_3659-1`, EVM chain id **3659**) ZETAPHY จ่ายเหรียญเข้าที่อยู่แบบ 0x (EVM) แต่ SWD อยู่ในกระเป๋า Solana
ผู้ถือจึงต้อง **ผูก** กระเป๋า Solana เข้ากับที่อยู่ 0x ของตัวเองหนึ่งครั้ง ด้วยการเซ็นข้อความสั้น ๆ หนึ่งบรรทัด
การเซ็นนี้ไม่มีค่าใช้จ่าย และไม่มีเหรียญเคลื่อนไหวแม้แต่หน่วยเดียว

## กติกาความปลอดภัย (อ่านก่อนทำอะไรทั้งนั้น)

- **ZETAPHY ไม่เคยขอวลีกู้คืน (seed) หรือคีย์ส่วนตัวของคุณ** ไม่ให้โอนเงินค่าอะไรทั้งสิ้น และไม่ให้อนุมัติธุรกรรมใด ๆ
  เพื่อผูกกระเป๋า ใครขอสิ่งเหล่านี้คือมิจฉาชีพ ไม่ว่าจะอ้างเป็นแอดมิน ทักแชทมาเอง หรือทำเว็บหน้าตาเหมือนของเราก็ตาม
- สิ่งเดียวที่คุณต้องเซ็นคือข้อความธรรมดาที่ขึ้นต้นด้วย `ZETAPHY airdrop: link` ถ้ากระเป๋าขึ้นว่า
  **"Approve transaction"** มีค่าธรรมเนียม ขออนุมัติโทเคน หรือแสดงว่ายอดเงินจะเปลี่ยน **ให้หยุดแล้วกดปฏิเสธทันที**
- ใช้เฉพาะลิงก์ในเอกสารนี้ ได้แก่หน้า `https://app.sawasdeecoin.com/airdrop-link.html` และฟอร์มใน repository นี้
  (`github.com/pospos191-alt/zetaphy`) เว็บหรือฟอร์มอื่นไม่ใช่ของเรา
- ZETAPHY จะไม่ทักหาคุณก่อน และไม่มีอะไรต้อง "ยืนยันกระเป๋า" "ซิงค์" หรือ "ปลดล็อก"
- การผูกกระเป๋าเป็น **ข้อมูลสาธารณะ** ใครก็เห็นได้ว่ากระเป๋า Solana นี้กับที่อยู่ 0x นี้เป็นของคนเดียวกัน
  ถ้าไม่สะดวกให้คนอื่นเห็น ก็ไม่ต้องผูก

## ใครมีสิทธิ์

- กระเป๋า Solana ทุกใบ (ที่อยู่เจ้าของกระเป๋า ที่เห็นใน Phantom, Solflare หรือ Backpack) ที่ถือ SWD อย่างน้อย 10 SWD
  ณ วันที่ 20 พ.ย. 2026 เวลา 14:00 UTC สแนปช็อตจะรวม SWD จากทุกบัญชีโทเคนของกระเป๋านั้น (ทั้ง SPL Token และ Token-2022)
- คุณต้องเซ็นข้อความด้วยกระเป๋านั้นได้ SWD ที่ฝากไว้ในกระดานเทรดหรืออยู่ในพูลสภาพคล่อง บนเชนถือเป็นของบัญชี
  กระดานเทรดหรือบัญชีพูล ไม่ใช่ของคุณ ถ้าอยากได้สิทธิ์ ให้ย้ายมาไว้ในกระเป๋าตัวเองก่อนเวลาสแนปช็อต
- ที่อยู่ที่ถูกตัดออก (ถ้ามี เช่น บัญชีของโครงการเอง) จะเผยแพร่พร้อมรายชื่อ
- รอบที่ 1 จ่ายเฉพาะกระเป๋าที่ผูกทันก่อนปิดรับ ส่วนของกระเป๋าที่ไม่ได้ผูกจะไม่ถูกจ่ายในรอบนี้ แต่ยังอยู่ในมัลติซิก
  ของแอร์ดรอป SWD และอาจนำไปจ่ายในรอบถัดไป

**คิดจำนวนที่ได้อย่างไร** แบ่ง 20,000,000 ZTPHY ตามสัดส่วน SWD ของทุกกระเป๋าที่มีสิทธิ์ ณ เวลาสแนปช็อต แต่ละกระเป๋า
ได้ไม่เกิน 5,000 ZTPHY ส่วนที่ถูกตัดเพราะเกินเพดานจะเฉลี่ยกลับไปให้กระเป๋าที่ยังไม่ถึงเพดาน เพดานนี้นับต่อกระเป๋า
Solana หนึ่งใบ ถ้าผูกกระเป๋า Solana หลายใบเข้ากับที่อยู่ 0x เดียวกัน ยอดของทุกใบจะรวมเป็นการรับครั้งเดียว

## วิธีผูกกระเป๋า (ใช้เวลาราว 2 นาที)

ต้องมี 3 อย่าง: กระเป๋า Solana ที่ถือ SWD, ที่อยู่ 0x ของคุณบน ZETAPHY (กระเป๋า EVM ใดก็มี เช่น MetaMask, Rabby,
Trust, OKX) และบัญชี GitHub (สมัครฟรี) ไว้ส่งการผูกขึ้นเว็บ

### วิธีง่าย: ใช้หน้าผูกกระเป๋า

1. เปิด **https://app.sawasdeecoin.com/airdrop-link.html** ในเบราว์เซอร์ที่มีกระเป๋า Solana ของคุณ
   - **Phantom** บนมือถือ: เปิดแอป Phantom ไปที่แท็บเบราว์เซอร์ (ไอคอนลูกโลก) แล้วพิมพ์ที่อยู่หน้าเว็บ
     บนคอมพิวเตอร์: ใช้ส่วนขยาย Phantom
   - **Solflare** บนมือถือ: เปิดแอป Solflare ไปที่เบราว์เซอร์ในแอป (Explore) แล้วพิมพ์ที่อยู่หน้าเว็บ
     บนคอมพิวเตอร์: ใช้ส่วนขยาย Solflare
   - **Backpack** บนมือถือ: เปิดแอป Backpack ไปที่เบราว์เซอร์ในแอป แล้วพิมพ์ที่อยู่หน้าเว็บ บนคอมพิวเตอร์: ใช้ส่วนขยาย Backpack
2. กด **เชื่อม Phantom / Solflare / Backpack** แล้วอนุมัติการเชื่อมต่อในกระเป๋า ขั้นนี้แค่ให้หน้าเว็บเห็นที่อยู่สาธารณะของคุณ
3. พิมพ์หรือวางที่อยู่ 0x ของคุณ หรือกด **ใช้ที่อยู่จากกระเป๋า EVM ของฉัน** ถ้ามีกระเป๋า EVM อยู่ในเบราว์เซอร์เดียวกัน
   หน้าเว็บจะตรวจ checksum แบบ EIP-55 ให้ ซึ่งจับที่อยู่พิมพ์ผิดได้เกือบทุกกรณี
4. อ่านข้อความบนหน้าเว็บ หน้าตาประมาณนี้:
   `ZETAPHY airdrop: link 7xKX…sAsU to 0xAbC…123 on 3659`
5. กด **เซ็นข้อความ (ฟรี)** กระเป๋าจะขึ้นหน้าจอ **"Sign message"** พร้อมข้อความเดียวกัน กดอนุมัติได้เลย
   ไม่มีค่าธรรมเนียม และไม่ใช่ธุรกรรม
6. หน้าเว็บจะตรวจลายเซ็นให้ทันทีและแสดงลายเซ็นออกมา กด **เปิดฟอร์ม GitHub ที่กรอกไว้ให้แล้ว** ตรวจช่องต่าง ๆ
   ติ๊กช่องยืนยันความปลอดภัย แล้วกด **Create** เท่านี้ก็เสร็จ

### ทำเอง (ไม่ใช้หน้าเว็บ)

1. เขียนข้อความเองให้ตรงทุกตัวอักษร (บรรทัดเดียว เว้นวรรคทีละหนึ่งช่อง ที่อยู่ 0x ต้องอยู่ในรูป checksum):
   `ZETAPHY airdrop: link <ที่อยู่ Solana ของคุณ> to <ที่อยู่ 0x ของคุณ> on 3659`
   หรือสั่งพิมพ์ข้อความด้วย `node zetaphy-network/airdrop/cli.js link-message <Solana> <0x> --chain-id 3659`
2. เซ็นข้อความด้วยฟังก์ชัน "sign message" ของกระเป๋า Solana จะได้ลายเซ็น ed25519 ขนาด 64 ไบต์
   ส่งเป็น base58, 0x-hex หรือ base64 ก็ได้
3. เปิด[ฟอร์ม](https://github.com/pospos191-alt/zetaphy/issues/new?template=airdrop-link.yml) กรอกที่อยู่ Solana
   ที่อยู่ 0x และลายเซ็น ติ๊กช่องยืนยัน แล้วกด **Create**

**Ledger และกระเป๋าฮาร์ดแวร์อื่น ๆ** กระเป๋าเหล่านี้เซ็นข้อความในรูปแบบ "off-chain message" ของ Solana ซึ่งได้ข้อมูลคนละแบบ
รอบที่ 1 จึงยังรับไม่ได้ ห้ามนำวลีกู้คืนของกระเป๋าฮาร์ดแวร์ไปกรอกในกระเป๋าซอฟต์แวร์เพื่อเลี่ยงข้อจำกัดนี้เด็ดขาด
ถ้าอยากเข้าร่วม ให้ย้าย SWD ไปไว้ในกระเป๋าซอฟต์แวร์ที่คุณควบคุมเองก่อนเวลาสแนปช็อต

**กรอกผิด?** ปิด issue เดิมแบบ **"not planned"** (ลูกศรข้างปุ่ม "Close issue") แล้วเปิด issue ใหม่ด้วยที่อยู่ที่ถูก
ถ้ากระเป๋า Solana ใบเดียวมีการผูกที่ยังเปิดอยู่สองรายการและชี้ไปที่อยู่ 0x ต่างกัน ทั้งสองรายการจะไม่ถูกนับ
จนกว่าจะเหลือรายการเดียว

## หลังปิดรับ: รายชื่อ Merkle root และวิธีตรวจสอบ

1. หลังวันที่ 4 ธ.ค. 2026 เวลา 14:00 UTC เจ้าของโครงการจะรวบรวม issue ตรวจลายเซ็นทุกรายการ แล้วสร้างรายชื่อ
   รายชื่อทั้งหมดจะเผยแพร่ใน repository นี้ พร้อมกับ:
   - `summary.json`: จำนวนผู้รับ ยอดรวม **Merkle root** และ `listSha256` ของ `list.csv`
   - `list.csv`: ทุกรายการ `index,address,amount` (จำนวนเป็นหน่วยย่อย ทศนิยม 18 ตำแหน่ง)
   - `shards/`: ไฟล์เล็กแยกตามที่อยู่ ไว้ค้นรายการของตัวเอง
   - รายงาน issue ที่ถูกปฏิเสธ ขัดแย้งกัน หรือซ้ำกัน พร้อมเหตุผลของแต่ละรายการ
   ไฟล์ชุดเดียวกันจะเปิดให้ดูที่ `https://app.sawasdeecoin.com/airdrop/` ด้วย และจะประกาศ root กับ `listSha256`
   ในทุกช่องทางทางการ
2. **ตรวจเองได้** ใครก็คำนวณ root ใหม่จากรายชื่อที่เผยแพร่ได้:
   ```bash
   cd zetaphy-network && npm ci
   node airdrop/cli.js verify <โฟลเดอร์รอบที่เผยแพร่>
   sha256sum <โฟลเดอร์รอบที่เผยแพร่>/list.csv     # ต้องตรงกับ listSha256 ใน summary.json
   ```
   เมื่อ deploy สัญญารับเหรียญ (`ZtphyMerkleDistributor`) แล้ว คำสั่งเดียวกันนี้จะตรวจ root ยอดรวม และจำนวนรายการ
   ในสัญญาเทียบกับรายชื่อให้ด้วย:
   ```bash
   node airdrop/cli.js verify <โฟลเดอร์> --rpc https://129-221-199-191.sslip.io --distributor 0x<ที่อยู่ที่ประกาศ>
   ```
   หาที่อยู่ 0x ของตัวเองได้ใน `list.csv` หรือในการ์ด "รับแอร์ดรอป" ของ hub ซึ่งใช้ได้โดยไม่ต้องเชื่อมกระเป๋า
3. **ช่วงตรวจสอบ** สัญญาจะได้รับเหรียญเท่ากับยอดรวมของรายชื่อพอดี และเปิดให้รับได้ตั้งแต่เวลาที่กำหนดไว้ตายตัว
   (`claimStart`) ซึ่งจะประกาศพร้อมรายชื่อ โดยเว้นเวลาให้ทุกคนตรวจสอบก่อน ถ้าพบว่ารายชื่อผิดก่อนมีใครได้รับเหรียญ
   รอบนี้ยกเลิกได้ และเหรียญจะกลับไปที่มัลติซิก เมื่อ deploy สัญญาแล้ว ไม่มีใครแก้รายชื่อหรือ root ได้อีก

## การรับเหรียญ และการเก็บเหรียญที่เหลือคืน

- ตั้งแต่วันเปิดรับไป **90 วัน** ที่อยู่ 0x แต่ละรายการในรายชื่อรับเหรียญได้ครั้งเดียว relayer ของโครงการจะส่งคำขอรับ
  ให้ทีละหลายรายการ (`claimMany`) และจ่ายค่าแก๊สให้ คุณจึงไม่ต้องมี ZTPHY จะกดรับเองที่การ์ด "รับแอร์ดรอป" ใน hub ก็ได้
  ไม่ว่าใครเป็นคนส่งคำขอ เหรียญจะเข้าที่อยู่ 0x ในรายชื่อเท่านั้น
- ครบ 90 วันแล้ว ใครก็เรียก `sweep()` ได้ เหรียญที่เหลือทั้งหมดจะไปที่ `0xaE842c15Ad4A6D6027597C3c3d44A4ada8FB0318`
  ซึ่งเป็นมัลติซิกของแอร์ดรอป SWD ที่อยู่นี้ถูกกำหนดไว้ในสัญญาตั้งแต่ตอน deploy และแก้ไขไม่ได้

```bash
# 2. แบ่งตามสัดส่วน 20,000,000 ZTPHY เพดาน 5,000 ZTPHY ต่อกระเป๋า ตัดเศษต่ำกว่า 10 SWD (SWD มีทศนิยม 5 ตำแหน่ง)
node airdrop/cli.js allocate snapshot.json --min 1000000 --pool 20000000 --cap 5000 > swd.json
# 3. หลัง 4 ธ.ค. 2026 14:00 UTC: ดึง issue การผูกตามที่ GitHub API ส่งกลับมา (ไม่ต้องกรองด้วย label)
gh api --paginate --slurp 'repos/pospos191-alt/zetaphy/issues?state=all&per_page=100' > issues.json
node airdrop/cli.js links-from-issues issues.json --chain-id 3659 --deadline 2026-12-04T14:00:00Z > links.json
node airdrop/cli.js link-solana swd.json links.json --chain-id 3659 > linked.json
# 4. สร้างรายชื่อ (เผยแพร่โฟลเดอร์นี้ พร้อมส่วน rejected / conflicts ของ links.json และ linked.json)
node airdrop/cli.js merkle linked.json --out round1 --chain-id 3659 --pool 20000000
node airdrop/cli.js verify round1
# 5. สัญญา: เปิดรับที่ <วันเปิดรับ> ปิดหลังจากนั้น 90 วัน เหรียญที่ไม่มีคนรับกลับไปที่มัลติซิก
node airdrop/cli.js init-code round1 --start <วันเปิดรับ ISO> --deadline <วันเปิดรับ + 90 วัน ISO> \
  --return-to 0xaE842c15Ad4A6D6027597C3c3d44A4ada8FB0318 [--guardian 0x<มัลติซิก>]
```

`links-from-issues` อ่านเนื้อหา issue ที่สร้างจากฟอร์ม (`.github/ISSUE_TEMPLATE/airdrop-link.yml`) และตรวจลายเซ็น
ทุกรายการสำหรับเชน 3659 ด้วยกติกาเดียวกับ `link-solana` แล้วรายงานรายการที่ถูกตัดออก ได้แก่ issue ที่สร้างหลัง
`--deadline` ไม่ได้ติ๊กช่องยืนยัน ที่อยู่หรือลายเซ็นผิด chain id ผิด รายการซ้ำ (นับครั้งเดียว) รายการขัดแย้ง
(กระเป๋า Solana ใบเดียวผูกหลายที่อยู่ 0x: ไม่นับ) และ issue ที่ปิดแบบ "not planned" (ถอนเองหรือถูกปฏิเสธ)
label `airdrop-link` (`gh label create airdrop-link`) ช่วยให้หา issue ง่ายขึ้น แต่ตัวรวบรวมไม่ได้พึ่ง label

deploy สัญญาแจกตามขั้นตอนใน [ZETAPHY-MAINNET-PROCEDURE.md](ZETAPHY-MAINNET-PROCEDURE.md) แล้วตรวจด้วย
`verify round1 --rpc https://129-221-199-191.sslip.io --distributor 0x…` จากนั้นโอนเหรียญเข้าสัญญาจากมัลติซิก
เท่ากับ `summary.total` พอดี ประกาศที่อยู่สัญญา root `listSha256` และวันเปิดรับ แล้วเมื่อถึงวันเปิดรับให้รัน relayer
ด้วย `claimMany` โอนเข้าสัญญาเฉพาะยอดรวมของ `linked.json` (ผู้ถือที่ผูกแล้ว) ส่วนของคนที่ไม่ได้ผูกยังอยู่ในมัลติซิก
