# swd_amm — การทดสอบแบบสุ่มเข้มข้น (fuzzing) และการพิสูจน์ทางคณิตศาสตร์ (formal verification)

*10 พ.ย. 2026 — ฉบับภาษาไทยแบบภาษาง่าย สำหรับเจ้าของโครงการ
รายละเอียดทางเทคนิคอยู่ใน [FUZZING_FORMAL.md](FUZZING_FORMAL.md)*

## สรุปสั้น ๆ

เราเพิ่ม "เครื่องตรวจอัตโนมัติ" 3 แบบ ให้คอยตรวจสูตรคำนวณของ AMM
(สระแลกเหรียญ) และตัวโปรแกรมจริงที่ build แล้ว

1. **Fuzzing** — คอมพิวเตอร์สุ่มลำดับการกระทำนับล้านแบบ เช่น ฝากเหรียญ
   ถอนเหรียญ แลกเหรียญ บริจาคเหรียญเข้ากองกลาง หรือสั่งการผ่าน governance
   จากผู้ใช้หลายคนพร้อมกัน แล้วเช็กทุกก้าวว่ากฎความปลอดภัยยังไม่ถูกละเมิด
   ทำไปทั้งหมดประมาณ **4.6 ล้านครั้ง** (ใช้เวลาเครื่องรวม 40 นาที)
2. **ทดสอบกับโปรแกรมจริง (LiteSVM)** — โหลดไฟล์โปรแกรม `.so` ตัวจริง
   แล้วยิงธุรกรรมสุ่ม **400,000 ครั้ง** ทุกธุรกรรมต้องให้ผล
   ตรงกับแบบจำลองทุกตัวเลข
3. **Kani** — ไม่ได้สุ่ม แต่ "พิสูจน์" ว่ากฎข้อนั้นจริงกับ **ทุกค่า**
   ในช่วงที่กำหนด พิสูจน์สำเร็จ **6 ข้อ** อีก 14 ข้อเขียนไว้แล้ว
   แต่เครื่องพิสูจน์ใช้เวลานานเกินไปจนทำไม่เสร็จ สำหรับ 14 ข้อนี้
   เราใช้วิธีรองลงมา คือไล่ตรวจ "ทุกค่า" ในช่วงตัวเลขเล็ก ๆ แทน
   ผ่านทุกข้อ

**ผล: พบบั๊กจริง 2 ตัว แก้แล้วทั้งคู่ ทั้งสองตัวไม่ทำให้เงินใครหาย**

- `isqrt(2)` (ฟังก์ชันหารากที่สอง) ตอบผิดเป็น 2 แทน 1
  ตอนนี้ยังไม่มีทางไปถึงจุดนี้ได้จริง แต่ถ้าวันหน้ามีคนนำไปใช้ต่อ
  ก็อาจเกิดปัญหาได้
- คำนวณราคาของ bin ที่หมายเลขติดลบสุดขั้ว (i32::MIN) แล้วโปรแกรม
  "พัง" (panic) แทนที่จะปฏิเสธอย่างเรียบร้อย ธุรกรรมนั้นถูกยกเลิกอยู่ดี
  เงินจึงไม่เสียหาย ตอนนี้แก้ให้ตอบ error อย่างถูกต้องแล้ว

ทั้งสองตัวมีการทดสอบกันพลาดถาวร (regression test) แล้ว นอกจากนี้ไม่พบ
กรณีใดที่ผิดกฎความปลอดภัยเลย

## กฎความปลอดภัยที่ตรวจ (ทั้ง 3 แบบสระ: CP, DLMM, SWDMM v2)

- **ไม่ล้มละลาย** — เหรียญในตู้เซฟ (vault) ต้องมีมากกว่าหรือเท่ากับ
  ทุกยอดที่สระติดค้างผู้อื่นเสมอ ได้แก่ เหรียญในสระ ค่าธรรมเนียมที่ LP
  ยังไม่ได้ถอน และค่าธรรมเนียมของโปรโตคอล
- **เสกเงินไม่ได้** — ฝากแล้วถอนทันที หรือแลก A→B แล้วแลกกลับ B→A
  จะไม่มีวันได้คืนมากกว่าที่ใส่ไป
- **ปัดเศษเข้าข้างสระเสมอ** — เงินที่ผู้ใช้ได้รับปัดลง
  เงินที่ผู้ใช้ต้องจ่ายและค่าธรรมเนียมปัดขึ้น
- **k ไม่ลดลงเมื่อแลกเหรียญ** และมูลค่าต่อหุ้น LP ไม่ลดลงไม่ว่าจะทำอะไร
- **DLMM** — bin ที่อยู่สูงกว่า bin ปัจจุบันมีแต่เหรียญ A ส่วน bin
  ที่ต่ำกว่ามีแต่เหรียญ B เสมอ และการแลกหนึ่งครั้งข้าม bin ได้ไม่เกิน 30 ช่อง
- **คนฝากคนแรกโกงไม่ได้ และบริจาคเหรียญเพื่อปั่นราคาหุ้นไม่ได้** — คนที่มาฝากทีหลัง
  เสียได้อย่างมากแค่เศษจากการปัดเท่านั้น
- **โปรแกรมไม่พัง** ไม่ว่าจะได้ตัวเลขแปลกแค่ไหน ต้องตอบเป็น error
  อย่างเรียบร้อยเท่านั้น
- **ถอนออกได้เสมอ** — เมื่อจบการทดสอบ ทุกคนต้องถอนเหรียญ
  และค่าธรรมเนียมของตัวเองออกได้ ไม่มีเงินติดค้าง

## สิ่งที่ "ไม่ได้" รับประกัน (สำคัญ โปรดอ่าน)

- **Fuzzing หาบั๊กได้ แต่พิสูจน์ไม่ได้ว่าไม่มีบั๊กเหลือเลย** มันตรวจได้
  เฉพาะกรณีที่สุ่มไปเจอ
- **Kani พิสูจน์เฉพาะฟังก์ชันคณิตศาสตร์ที่ระบุไว้ และเฉพาะช่วงตัวเลขที่กำหนด**
  (ดูตารางในฉบับอังกฤษ) ไม่ได้พิสูจน์ทั้งโปรแกรม
- **ไม่ได้ตรวจเรื่องสิทธิ์และบัญชี** เช่น ใครเซ็นธุรกรรม ใครเป็นเจ้าของบัญชี
  หรือที่อยู่ PDA ถูกต้องหรือไม่ เรื่องเหล่านี้ตรวจโดย security review
  และชุดทดสอบโจมตีที่มีอยู่แล้ว
- **ไม่ได้ตรวจ oracle (ราคาจาก Pyth)** และไม่ได้ตรวจ Token-2022
  ส่วนการแลกเหรียญของสระ CP/DLMM บนโปรแกรมจริงยังไม่ได้ทดสอบด้วยวิธีนี้
  (ทดสอบเฉพาะสูตรคำนวณ)
- **ไม่ได้ป้องกันการโจมตีทางเศรษฐกิจจากตลาดภายนอก** เช่น การปั่นราคา
  oracle หรือการทำ sandwich
- **ไม่ใช่การ audit** — ก่อนเปิดใช้บน mainnet ยังต้องทำตาม checklist
  ใน SECURITY.md ครบทุกข้อ รวมถึงจ้าง audit อิสระ

## ทำงานอัตโนมัติอย่างไร

- ทุก PR: CI จะเล่นซ้ำกรณีทดสอบที่เก็บไว้ทั้งหมด (รวมกรณีที่เคยเจอบั๊ก)
  ใช้เวลาไม่กี่นาที และยิงธุรกรรมสุ่มใส่โปรแกรมจริงหลัง `anchor build`
- ทุกวันอาทิตย์ หรือเมื่อกดสั่งเอง: รัน fuzzing แบบยาว และพิสูจน์ Kani ทุกข้อ
  (ไฟล์ `.github/workflows/amm-formal.yml`)
- ถ้าวันหนึ่ง CI แดงที่งาน `amm-fuzz` หรือ `amm-formal` แปลว่าการแก้โค้ด
  ครั้งนั้นไปทำให้กฎความปลอดภัยข้อใดข้อหนึ่งพัง **อย่า merge**
  ให้นักพัฒนาดูก่อน
