# โครงการล่าบั๊ก SWD AMM (ร่าง แบบ Immunefi) — สรุปสำหรับเจ้าของโครงการ

> **ยังเป็นร่าง ยังไม่เปิดจริง** จะยังไม่มีการจ่ายเงินจนกว่าเจ้าของจะทำครบ 3 ข้อ
> 1. กรอกตัวเลขทุกช่องที่เป็น `____` ในไฟล์ภาษาอังกฤษ
> 2. โอนเงินรางวัลเข้ากองทุนที่ Squads multisig ถืออยู่
> 3. ประกาศว่าเปิดแล้ว (บน Immunefi หรือในไฟล์นี้) พร้อมวันที่
>
> ก่อนถึงตอนนั้น รางวัลมีแค่ "เครดิต" คือขึ้นชื่อใน Hall of Fame และในประกาศแก้ไข
> ไฟล์นี้ครอบคลุมเฉพาะ **SAWASDEE COIN (SWD) / SWD AMM** ส่วนเชน ZETAPHY และ bridge ใช้ `docs/BUG_BOUNTY.th.md`

## ขอบเขต (อะไรที่ให้หาบั๊ก)

- **หลัก:** โปรแกรม `swd_amm` บน Solana รุ่น mainnet (`mainnet,v2-only`) ได้แก่ pool v2, ตำแหน่ง LP, governance/timelock, ปุ่มหยุดฉุกเฉิน, ตัวกันราคา Pyth
- ส่วนที่ใช้แค่บน devnet (pool แบบ CP และ DLMM): รางวัลต่ำกว่าตารางหนึ่งขั้น
- เครื่องมือ build/ปล่อยรุ่น/ย้อนรุ่น/เฝ้าดู: ถ้ามีวิธีทำให้โค้ดที่ไม่ใช่รุ่นที่ประกาศขึ้นไปอยู่บนเชนได้ หรือทำให้ตัวตรวจบอกว่าโค้ดปลอมเป็นของจริง
- **เว็บแอป** `test-ui/` (เว็บ swap/pool) และ **integrations** (SDK, ตัวเชื่อม Jupiter และอื่นๆ ใน `integrations/`)
- สคริปต์ governance / Squads: ถ้าบั๊กทำให้กรรมการเซ็นสิ่งที่ต่างจากที่หน้าจอแสดง

**ไม่อยู่ในขอบเขต:** เรื่องที่รู้อยู่แล้วใน `KNOWN_ISSUES.md` · การที่ผู้ถือกุญแจสิทธิ์สูง (Squads vault, governance, emergency) ทำชั่วเอง
(แต่ "วิธีแย่งสิทธิ์นั้นมา" อยู่ในขอบเขต) · บั๊กของบริการภายนอก (Solana, Anchor, Pyth, Squads, กระเป๋า) ·
ผู้ออกเหรียญแช่แข็งเหรียญตัวเอง · MEV ที่อยู่ในกรอบ slippage ที่ผู้ใช้ยอมรับ · การยิงโหลด/DoS · หลอกลวง/ฟิชชิ่ง ·
**การทดสอบบน mainnet หรือกับเงินของคนอื่น**

## ระดับความรุนแรงและรางวัล (ใช้เกณฑ์ Immunefi v2.3)

| ระดับ | ตัวอย่าง | รางวัล (เจ้าของกรอกเอง) |
|---|---|---|
| วิกฤต (Critical) | ขโมยเงินในพูล/ตำแหน่ง LP/ค่าธรรมเนียม · แช่แข็งเงินถาวร · ได้สิทธิ์ governance/emergency/upgrade หรือข้าม timelock / M-of-N · ทำให้เว็บหรือ SDK สร้างธุรกรรมที่ดูดเงินผู้ใช้ | **10% ของเงินที่เสี่ยง** ขั้นต่ำ `____` สูงสุด **`____` USD (เพดาน)** |
| สูง (High) | ขโมย/แช่แข็งค่าธรรมเนียมของโปรโตคอล · แช่แข็งเงินผู้ใช้ชั่วคราว · หยุด/เปิดพูลโดยไม่มีสิทธิ์ · หน้าเว็บโชว์ข้อมูลผิดจนผู้ใช้เสียเงิน | `____` USD (แนะนำ 10–20% ของเพดาน) |
| กลาง (Medium) | ก่อกวนจนพูลใช้ไม่ได้โดยไม่ได้กำไร · ข้ามคำเตือนความปลอดภัยของกระเป๋า | `____` USD (แนะนำ 2–5%) |
| ต่ำ (Low) | ทำงานไม่ตรงเอกสาร แต่ไม่เสียเงิน | `____` USD (แนะนำ 0.5–1%) |

วิธีตั้งเพดานแบบที่นิยมกัน: เพดาน = **10% ของ TVL** ที่ต้องการปกป้อง แต่ต้องไม่เกินเงินในกองทุน
ตัวอย่าง: TVL 500,000 ดอลลาร์ → เพดาน 50,000 ดอลลาร์

## กติกาสั้นๆ

- พิสูจน์บนเครื่องตัวเอง (local validator / test) เท่านั้น ห้ามแตะ mainnet และห้ามแตะเงินของคนอื่น
- ห้ามเปิดเผยก่อนแก้เสร็จ ห้าม DoS ห้ามหลอกลวง หนึ่งรายงานต่อหนึ่งปัญหา
- **Safe harbor:** ถ้าทำตามกติกาโดยสุจริต ทีมจะไม่ฟ้องและไม่แจ้งความ (มีผลกับทีมผู้ดูแลเท่านั้น และไม่ใช่คำแนะนำทางกฎหมาย)

## ช่องทางแจ้ง (ต้องตรงกันทุกที่)

1. **GitHub → Security → Report a vulnerability** ช่องทางหลัก เจ้าของต้องเปิดใช้ก่อนที่ Settings → Code security
2. อีเมล **`security@sawasdeecoin.com`** ถูกเขียนไว้ใน `security.txt` ที่ฝังอยู่ในโปรแกรมแล้ว
   **แต่กล่องอีเมลนี้ยังไม่ได้สร้าง (เจ้าของต้องสร้างและเปิดอ่านประจำ)** ระหว่างนี้ให้ใช้ช่องทาง 1
3. Immunefi: ใส่ลิงก์เมื่อขึ้นทะเบียนแล้ว

## เจ้าของต้องทำอะไร

1. เปิด Private vulnerability reporting บน GitHub
2. สร้างกล่องอีเมล `security@sawasdeecoin.com` แล้วมีคนเปิดอ่านทุกวัน (ถ้าจะใช้อีเมลอื่น ต้องแก้ `security.txt` ในรุ่นถัดไปที่ผ่านการ audit แล้ว)
3. ตัดสินใจเพดานรางวัลและตัวเลขแต่ละระดับ แล้วกรอกลงในไฟล์ภาษาอังกฤษ
4. โอนเงินรางวัลเข้า Squads vault แล้วประกาศว่าเปิด (ทำหลัง audit และก่อนรับเงินจริงบน mainnet)
5. ถ้าจะลง Immunefi ให้ส่งไฟล์ภาษาอังกฤษนี้เป็นร่าง (เขาช่วยปรับให้ตรงรูปแบบ)
