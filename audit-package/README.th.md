# คู่มือจ้างตรวจสอบความปลอดภัย (Audit) — SWD AMM

สำหรับเจ้าของโครงการ SWD (อ่านได้โดยไม่ต้องเป็นโปรแกรมเมอร์)
อัปเดต 11 พ.ย. 2026

> **สถานะวันนี้:** โปรแกรม SWD AMM ยัง **ไม่เคยถูกตรวจโดยบริษัทภายนอก** และ **ยังไม่ได้ขึ้น mainnet**
> ห้ามนำเงินจริงเข้าระบบจนกว่าจะได้รายงาน audit และแก้ไขครบ
> ห้ามส่ง private key / seed phrase ให้ใคร รวมถึงบริษัท audit — เขาไม่ต้องใช้เลย ใช้แค่ลิงก์ GitHub

---

## ✅ สัปดาห์นี้ทำ 5 อย่าง

1. **ตั้งอีเมลติดต่อของโครงการ** (เช่น `security@sawasdeecoin.com` ที่มีคนเปิดอ่านจริง) แล้วแจ้งนักพัฒนา
   — ใช้ทั้งในอีเมลขอราคาและใน `security.txt` ของโปรแกรม
2. **ส่งอีเมลขอราคา (RFP) ไป 5 บริษัทในวันเดียวกัน**: Accretion, Neodyme, Zellic, OtterSec, Sec3
   — คัดลอกข้อความจาก `audit-package/rfp/RFP_EMAIL.md` เติมชื่อ/อีเมลของคุณในช่อง `[…]`
   แล้ววางประโยคเปิดเฉพาะของแต่ละบริษัทจาก `audit-package/rfp/FIRMS.md` ไว้ย่อหน้าแรก
   (ก่อนส่ง เปิดเว็บของบริษัทเพื่อตรวจช่องทางติดต่ออีกครั้ง)
3. **สมัครโครงการช่วยค่า audit ของ Solana** (Solana Audit Subsidy — Areta / Superteam ลดได้ราว 30% ถ้าผ่าน)
   — ดูวิธีใน `audit-package/rfp/CONTESTS_AND_SUBSIDIES.md` และถามทุกบริษัทว่าร่วมโครงการนี้หรือไม่
4. **เตรียมงบและตัดสินใจขอบเขต**: ใช้ขอบเขตเล็ก "v2-only" (แนะนำ ดูด้านล่าง) และตั้งงบเบื้องต้น
   (ประมาณการคร่าว ๆ ด้านล่าง — ราคาจริงต้องรอใบเสนอราคา)
5. **นัดคุยกับบริษัทที่ตอบกลับ** แล้วกรอกตารางเปรียบเทียบ (ด้านล่าง) — **ยังไม่ต้องจ่ายเงิน**
   จนกว่าจะได้ใบเสนอราคาอย่างน้อย 3 ราย

---

## 1. เราตัดขอบเขตให้ถูกลงแล้ว (สำคัญ)

ค่า audit คิดตามปริมาณโค้ดและความซับซ้อน โปรแกรมเดิมมีสระ 3 แบบ แต่บน mainnet เราจะใช้แค่ **SWDMM v2**
นักพัฒนาจึงทำ "สวิตช์ตอนสร้างโปรแกรม" ชื่อ `v2-only` ที่ **ตัดโค้ดสระแบบเก่า (CP และ DLMM) ออกจากไฟล์โปรแกรมจริง**
(ไม่ใช่แค่ "ไม่ใช้")

| | โปรแกรมเต็ม | แบบ mainnet (v2-only) |
|---|---|---|
| ปริมาณโค้ดที่ต้องตรวจ (nSLOC) | 4,745 บรรทัด | **2,531 บรรทัด (ลดลง ~47%)** |
| จำนวนคำสั่ง | 38 | 23 |
| ขนาดโปรแกรม | 1.28 MB | 0.79 MB |
| ค่าเช่าพื้นที่บน Solana ตอน deploy | ต้องมี ~17.9 SOL ในกระเป๋า | ต้องมี **~11.2 SOL** (ค้างไว้จริง ~5.7 SOL) |

สคริปต์ deploy (`scripts/deploy-mainnet.sh`) สร้างแบบ v2-only ให้อัตโนมัติแล้ว

---

## 2. ราคาและเวลา — ต้องพูดตรง ๆ ว่ายังไม่แน่นอน

- **บริษัท audit ส่วนใหญ่ไม่ประกาศราคา** ต้องขอใบเสนอราคาเท่านั้น
- ตัวเลขจากบทความทั่วไป (ไม่ได้ยืนยัน และบางบทความเขียนโดยบริษัทที่ขาย audit เอง):
  โปรแกรม Solana ขนาดเล็ก ~US$7,000–20,000, โปรโตคอล DeFi ทั่วไป ~US$60,000–130,000
- สำหรับขอบเขตของเรา (~2.5k บรรทัด, AMM + governance) **เดาคร่าว ๆ ว่าน่าจะอยู่ราว US$15,000–60,000**
  ขึ้นกับบริษัท จำนวนสัปดาห์ และคิวงาน — **นี่เป็นการเดา ไม่ใช่ราคาจริง** ราคาอาจสูงหรือต่ำกว่านี้ได้
- ถ้าได้โครงการช่วยค่า audit อาจลดได้ราว 30% (ถ้าผ่านการคัดเลือก และบริษัทนั้นร่วมโครงการ)
- เวลาโดยทั่วไป: ตอบกลับ 1–7 วัน → คิวเริ่มงาน 1–8 สัปดาห์ (บริษัทใหญ่คิวยาว) → ตรวจ 1–3 สัปดาห์
  → เราแก้ 1–2 สัปดาห์ → ตรวจการแก้ (fix review) 2–7 วัน → รายงานฉบับสาธารณะ
  **รวมโดยประมาณ 1.5–3 เดือน** จากวันที่ส่งอีเมล

## 3. ส่งอะไรให้บริษัท

ส่งแค่ **ลิงก์** — ทุกอย่างอยู่ใน GitHub สาธารณะแล้ว:

- https://github.com/pospos191-alt/zetaphy
- ไฟล์ `AUDIT_README.md` (หน้าแรกสำหรับผู้ตรวจ) และโฟลเดอร์ `audit-package/`
- **ห้ามส่ง**: private key, seed phrase, ไฟล์ keypair, รหัสผ่านใด ๆ

เมื่อตกลงจ้างแล้ว นักพัฒนาจะ "แช่แข็ง" โค้ด (freeze commit) และใส่เลข commit ใน `audit-package/SCOPE.md`
ระหว่าง audit **ห้ามแก้โค้ดในขอบเขต** (ถ้าแก้ ราคาและเวลาอาจเพิ่ม)

## 4. เปรียบเทียบใบเสนอราคาอย่างไร

กรอกตารางนี้สำหรับทุกบริษัท:

| เรื่อง | บริษัท A | บริษัท B | บริษัท C |
|---|---|---|---|
| ราคารวม (USD) | | | |
| จำนวนสัปดาห์ × จำนวนผู้ตรวจ | | | |
| วันเริ่มงานเร็วที่สุด | | | |
| **รวมการตรวจการแก้ (fix review) ไหม** กี่รอบ | | | |
| **รายงานเปิดเผยสาธารณะได้ไหม** | | | |
| เคย audit AMM/DEX บน Solana ไหม (ขอลิงก์รายงาน) | | | |
| ตรวจ Token-2022, Pyth, Squads, และคำถาม Jupiter (Q1) ไหม | | | |
| ร่วมโครงการช่วยค่า audit ไหม | | | |
| เงื่อนไขการจ่ายเงิน (มัดจำกี่ %) | | | |

**หลักเลือก (เรียงตามความสำคัญ):**
1. ต้องมี **fix review** และ **รายงานสาธารณะ** — ถ้าไม่มี Jupiter/DefiLlama/ผู้ใช้จะไม่เชื่อถือ
2. มีประสบการณ์ Solana DeFi จริง (ดูรายงานเก่า)
3. ราคาต่อ "สัปดาห์-คน" สมเหตุสมผล — ราคาถูกมากแต่ตรวจแค่ 3–4 วัน มักได้งานไม่ละเอียด
4. วันเริ่มงานไม่ช้าเกินแผน

## 5. ตารางช่วยตัดสินใจ

| สถานการณ์ | แนะนำ |
|---|---|
| ได้ราคาไม่เกินงบ จากบริษัทที่มีชื่อด้าน Solana + มี fix review + รายงานสาธารณะ | **จ้างบริษัทนั้น** (ทางหลัก) |
| ราคาทุกเจ้าเกินงบมาก | ขอ "ขอบเขตย่อ" (เน้น swdmm_v2 + timelock) หรือสมัครโครงการช่วยค่า audit ก่อน แล้วค่อยจ้าง |
| คิวบริษัทใหญ่ยาวเกิน 2 เดือน | เลือกบริษัทเล็กที่เชี่ยวชาญ Solana (เช่น Accretion, Offside Labs, MadShield) |
| มีงบเหลือหลัง audit หลัก | จัดการแข่งขันหาบั๊ก (Code4rena / Sherlock / Cantina) เป็นชั้นที่สอง |
| ไม่มีงบ audit เลย | **อย่าขึ้น mainnet ด้วยเงินจริง** — ใช้ devnet ต่อ หรือขึ้นแบบจำกัดเงินในสระต่ำมากพร้อมคำเตือนชัดเจน (เสี่ยง ไม่แนะนำ) |
| บริษัทเสนอ "ตรวจแบบเร่งด่วน 2–3 วัน" ราคาถูก | ระวัง — ถามว่าครอบคลุมทุกไฟล์ในขอบเขตไหม และมี fix review ไหม |

## 6. หลังได้รายงาน ทำตามลำดับนี้

1. **นักพัฒนาแก้ทุกข้อระดับ Critical / High** (และ Medium ที่ทำได้) บน branch ใหม่
2. **ส่งให้บริษัทตรวจการแก้ (fix review)** จนได้รายงานฉบับสุดท้าย
3. **เผยแพร่รายงาน** (ลิงก์บนเว็บ, GitHub `audits/`, ในคำขอ Jupiter/DefiLlama)
4. **อัปเดต `security.txt`** ในโปรแกรม (`programs/swd_amm/src/lib.rs`): เปลี่ยน `auditors: "None yet"`
   เป็นชื่อบริษัท และใส่อีเมลความปลอดภัยจริงใน `contacts`
5. **บันทึก commit ที่ผ่าน audit** ใน `docs/MAINNET_RUNBOOK.md` Gate 4 และค่า sha256 ของไฟล์โปรแกรม
   (ใช้ตัวแปร `AUDITED_SHA256` — สคริปต์จะไม่ยอม deploy ถ้าไฟล์ไม่ตรงกับที่ตรวจ)
6. **รันสคริปต์ deploy แบบซ้อมก่อน** (`bash scripts/deploy-mainnet.sh all` = ไม่ส่งอะไรจริง)
   แล้วค่อย `--execute` ตามคู่มือ `docs/MAINNET_RUNBOOK.md` และ `docs/DEFI_LISTING.th.md`
7. เปิด **bug bounty** หลังขึ้น mainnet (`docs/BUG_BOUNTY.md`)
