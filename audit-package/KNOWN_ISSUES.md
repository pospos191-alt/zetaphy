# Known issues and accepted risks

These are known to the team. Please don't spend time re-discovering them, but **do
tell us if you think one is rated too low or the mitigation does not hold**. Severity
is our own estimate. "Mainnet build" = `--features mainnet,v2-only`.

| ID | Issue | Our severity | Status / mitigation |
|---|---|---|---|
| K-1 | **Mint freeze authority.** The program cannot see or refuse a mint's freeze authority. If the issuer freezes a pool vault, every withdrawal, claim and swap touching it fails, for both sides of the pool (funds stuck until unfrozen). Same for a Token-2022 mint with `DefaultAccountState = Frozen` (vaults are born frozen; the pool is unusable). | Medium (trusted-issuer risk) | Accepted. Governance must review freeze authority / default state of every mint before `set_mint_policy` (runbook Gate 3). |
| K-2 | **Pyth pull-oracle update choice.** For oracle-guarded pools, any genuine `Full`-verified `PriceUpdateV2` within `max_staleness_secs` (≤ 3,600 s) is accepted, so a trader can pick the most favourable recent price. A `publish_time` ahead of the cluster clock counts as age 0 (as in Pyth's SDK). The guard is optional per v2 pool; memecoin pools have none. | Low–Medium | Accepted. Use short windows (≤ 60 s) for guarded pools. The guard only refuses swaps; it does not price them. |
| K-3 | **Single-step authority rotation.** `set_authorities` replaces both keys in one instruction (no propose / accept). A typo to a valid but unowned key bricks governance (no unpause, no fee withdrawal, no policy changes) — only the all-zero key is refused. Not timelocked. | Medium (operational) | Accepted for v1; rotation happens through a Squads proposal that members review. Two-step rotation is a candidate change if the auditor recommends it. |
| K-4 | **Instant governance actions.** `set_mint_policy`, `set_mint_feed`, `set_pool_creation_paused`, `set_authorities` are not timelocked. | Low | Accepted. None of them can move funds or change an existing pool; they affect new pools / admin keys only. |
| K-5 | **Fee-tier squatting.** One v2 pool per (mint_a, mint_b, floor_fee_bps). Whoever creates it first fixes its fee schedule, dynamic-fee params, collect mode, activation and impact cap for good. Mint order is not canonical, so (A,B) and (B,A) can both exist. | Low | Accepted. Mitigation: governance pauses creation and creates the canonical launch pools itself (`creation_allowed` lets governance create while paused; runbook Gate 8). |
| K-6 | **Market-cap scheduler uses the pool's own spot price.** A trader can push the price within one transaction to lower the scheduled base fee for a following trade. | Low | Bounded by the per-swap and per-slot impact caps and by the fees paid to move the price. |
| K-7 | **Simplified volatility (dynamic) fee.** Linear accumulator; a holder can keep the fee high with dust swaps while the price sits away from the frozen reference. | Low | Meteora-style design; costs the attacker fees on every swap and only raises the fee other traders pay, up to `max_dynamic_fee_bps` (≤ 10%). |
| K-8 | **Position transfer is a plain field update.** No NFT, no two-step; transferring to a wrong key loses the position (the default key is refused). | Low | Accepted. |
| K-9 | **Deploy window.** Between deploy and handover the deployer is upgrade authority and governance. | Low (procedural) | `initialize_global_config` is gated on the upgrade authority (no front-run). `scripts/deploy-mainnet.sh` does init → handover in one session; upgrade authority moves last. |
| K-10 | **Emergency key can pause indefinitely**, including fee claims (a withdraw pause stops claims on purpose). | Low (griefing, no theft) | Unpause = multisig + 24 h timelock; governance can rotate the emergency key instantly. |
| K-11 | **Rounding dust.** Fee growth and pending fees round down; dust stays in the vault forever (no sweep). | Informational | Intentional (solvency first). |
| K-12 | **Upgradeable program.** The upgrade authority (Squads vault) can replace all code. | Informational | Disclosed to users; Squads vault, optionally with a Squads time lock. |
| K-13 | **Hand-written external layouts.** `PriceUpdateV2` (Pyth) and the Squads v4 `Multisig` offsets are parsed by hand (the official Pyth SDK does not build with anchor-lang 0.31.1). | Low | Owner + discriminator + length checked for Pyth; Squads parsing is used only by the read-only `verify_governance_multisig`. Layouts cross-checked against the SDKs and, for Squads, against a cloned mainnet program in `tests/z-squads-live-verification.ts`. Please review. |
| K-14 | **IDL error table is incomplete and mis-numbered.** Anchor 0.31.1 puts only one `#[error_code]` enum in the IDL (currently `TimelockError`) and numbers it from 6000 instead of its real 8500 offset. On-chain codes are correct. | Informational (client UX) | Use `audit-package/ERROR_CODES.md`; the web app uses a generated table (`test-ui/tests/gen-program-errors.mjs`). |
| K-15 | **`PendingAction` accounts are never closed**; their rent (paid by the proposer) stays locked. | Informational | Accepted (a few per year). |
| K-16 | **`fee_per_liquidity` (u128) overflow** after > ~2⁶⁴·L raw units of LP fees; the checked add would then refuse swaps. | Informational | Not reachable in practice (`docs/FUZZING_FORMAL.md` §6). |
| K-17 | **Compute units not modelled.** LiteSVM ran with a 1.4 M CU budget; worst-case `swap_v2` with the oracle guard and dynamic fee has not been profiled against the default 200 k CU limit. | Low (liveness) | Clients set a compute-unit limit. Profiling welcome. |
| K-18 | **`swap_v2` requires the trader to own both token accounts** (`token::authority = trader`). May not fit aggregator routing that pays out to a different account. | Design question | See QUESTIONS.md Q1. |
| K-19 | **Disabling a `MintPolicy` only stops new pools**; existing pools keep trading. | Informational | Intentional (no admin power over live pools); emergency pause covers incidents. |
| K-20 | **Not in the mainnet binary:** DLMM swap fee can be up to 1 raw unit below nominal (`floor(in·10000/(10000−fee))`); `add_dlmm_liquidity` has no min-shares argument; CP/DLMM require an oracle on every swap. | — | Out of scope (`v2-only` compiles CP and DLMM out). Listed so a full-build review knows them. |
| K-21 | **Build warning in Anchor-generated code**: `AccountInfo::realloc` is deprecated (from the `#[program]` macro expansion, not our code). | Informational | Anchor 0.31.1 behaviour. |
